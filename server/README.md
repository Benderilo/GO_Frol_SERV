# Frolov CRM — сервер

Go-сервер: публичный сайт + JSON API для Android-приложения.
Один бинарник, база — SQLite (драйвер на чистом Go, без cgo), шаблоны и статика
вшиты в исполняемый файл через `embed`.

## Запуск локально

```bash
cd server
go run ./cmd/server
```

Откроется на `http://localhost:8080`. Логин/пароль администратора по умолчанию —
`admin` / `admin` (только в dev-режиме, меняется переменными окружения).

## Переменные окружения

| Переменная                | По умолчанию      | Назначение                                    |
|---------------------------|-------------------|-----------------------------------------------|
| `FROLOV_ENV`              | `dev`             | `prod` включает JSON-логи и требует секрет     |
| `FROLOV_ADDR`             | `:8080`           | Адрес без TLS (только для локальной отладки)   |
| `FROLOV_DOMAIN`           | пусто             | Домен(ы) через запятую — включает HTTPS        |
| `FROLOV_HTTPS_ADDR`       | `:443`            | Адрес для TLS                                  |
| `FROLOV_ACME_EMAIL`       | пусто             | Почта для уведомлений Let's Encrypt            |
| `FROLOV_CERT_DIR`         | `<данные>/certs`  | Хранилище выданных сертификатов                |
| `FROLOV_DB`               | `data/frolov.db`  | Путь к файлу базы                              |
| `FROLOV_JWT_SECRET`       | случайный в dev   | Секрет подписи токенов, обязателен в prod      |
| `FROLOV_TOKEN_TTL`        | `720h`            | Срок жизни токена                              |
| `FROLOV_ADMIN_LOGIN`      | `admin`           | Логин администратора при первом запуске        |
| `FROLOV_ADMIN_PASSWORD`   | `admin`           | Пароль администратора при первом запуске       |
| `FROLOV_CORS_ORIGINS`     | `*`               | Список origin через запятую                    |

Администратор создаётся только один раз — при пустой базе. Существующий пароль
переменными не перетирается, его меняют из приложения.

## Фотографии заказов

`POST /api/v1/admin/orders/{id}/photos` принимает multipart с полем `photo`
и необязательной подписью `caption`. Файл до 8 МБ, форматы JPEG, PNG, WebP,
разрешение до 30 Мп. Сервер ужимает снимок до 1600 px по длинной стороне и
делает превью 480 px, оба в JPEG. Оригинал не хранится — на диске 6,7 ГБ.

Файлы лежат в `FROLOV_UPLOADS` (по умолчанию рядом с базой) и раздаются по
непредсказуемому токену. Токена мало: доступ проверяется — администратор
видит все снимки, клиент только по своим заказам, остальные получают 403.

## Личный кабинет клиента

Клиент входит на `/cabinet` по телефону и коду доступа. Код выдаёт менеджер:
`POST /api/v1/admin/clients/{id}/access` возвращает его ровно один раз, в базе
остаётся только bcrypt-хеш. Телефон сравнивается по последним десяти цифрам,
поэтому `+7 (900) 111-22-33`, `89001112233` и `79001112233` — один номер.

Сессия живёт 30 дней в HttpOnly-куке. `DELETE .../access` закрывает вход
немедленно: следующий запрос кабинета получит 401.

В кабинете клиент видит только свои заказы: статус, описание, стоимость, срок
и фотографии. Внутренние поля карточки — заметка и метка — наружу не отдаются.

`PUT /api/v1/admin/site` принимает частичный JSON: сервер берёт текущий документ
и накладывает присланные поля, поэтому приложение может слать только изменённую секцию.

## HTTPS

Если задан `FROLOV_DOMAIN`, сервер сам получает сертификат Let's Encrypt и
слушает 443-й порт. На 80-м он отвечает только на проверку владения доменом,
всё остальное перенаправляет на HTTPS постоянным редиректом. Закрывать 80-й
нельзя: без него сертификат не продлить.

Сертификат выдаётся на имя, поэтому на голом IP HTTPS невозможен. Домен
должен указывать на сервер **до** первого запуска — проверка идёт по имени.

Приложение ходит только по HTTPS: незашифрованные запросы запрещены на
уровне системы, исключение оставлено лишь для localhost при отладке.

## Развёртывание

Один раз разложите ключ, чтобы дальше не вводить пароль совсем:

```bash
ssh-copy-id root@91.184.246.64
```

Затем разворачивайте:

```bash
DOMAIN=v3002851.hosted-by-vdsina.ru ./deploy/deploy.sh 91.184.246.64
```

Всё уезжает одним SSH-соединением: бинарник, юнит и сценарий установки
идут одним архивом в stdin, поэтому пароль спрашивают один раз, а не за
каждый файл.

Скрипт прогоняет `go vet` и тесты, собирает бинарник под `linux/amd64`, копирует
по SSH, заводит системного пользователя `frolov`, ставит systemd-юнит и
открывает в ufw порты 22, 80 и 443. Без `DOMAIN` развёртывание останавливается:
по незащищённому HTTP сервис больше не поднимается.

### Перенос на другой сервер

```bash
./deploy/migrate.sh 195.19.195.169 91.184.246.64
```

Переносит каталог данных целиком — базу вместе с журналом WAL и фотографии.
Новый сервер должен быть уже развёрнут. Прежние данные на нём не удаляются,
а отодвигаются в `data.before-<метка времени>`.
При первом запуске создаётся `/etc/frolov-crm.env` со случайным паролем
администратора — он один раз печатается в вывод, запишите его.

Полезное на сервере:

```bash
systemctl status frolov-crm
journalctl -u frolov-crm -f
```
